## Test-first contract

behavior under test:
- An existing Artifacts index generated by the already-installed 0.1.121 runtime can create a private share after upgrading, even though that cached index does not know about the new local CSRF header.
- The compatibility path is still restricted to exact same-origin loopback requests; cross-origin requests remain denied.
- New Artifacts pages may continue to send the local capability as defense-in-depth, and an explicitly wrong capability must not be accepted.
- Signed remote workspace-edge requests remain unchanged.

existing local pattern:
- The local OS server is loopback-only and browser mutations can be protected by exact Origin validation. The artifact-sharing route already distinguishes loopback from signed remote traffic.

- Update `packages/os/tests/artifact-sharing-links.test.ts` so an exact-origin loopback POST with no capability succeeds (pre-upgrade page compatibility).
- Preserve negative wrong-origin coverage and add an invalid-capability denial.
