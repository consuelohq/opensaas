## summary
This PR is a massive synchronization of the `os` package and related infrastructure, primarily focusing on the reliability of the system daemon's lifecycle, MCP (Model Context Protocol) transport upgrades, and website asset updates. It introduces a critical fix for daemon self-mutation guards to prevent race conditions during updates and implements a dual-era transport for MCP to maintain backward compatibility.

## issues

1. **Massive PR Scope / Lack of Atomicity**
   - severity: 🔴 blocking
   - file: global
   - The PR mixes system-level daemon logic, MCP protocol changes, website CSS/SVG updates, and a large number of `.task` metadata files. This makes the review process error-prone and makes reverting specific features (e.g., just the website changes) impossible. 
   - **Fix**: Split this into at least three PRs: 
     1. OS Daemon & Lifecycle (the "reliable handoff" core).
     2. MCP Transport & Security Hardening.
     3. Website assets and Astro components.

2. **Commit Pollution (Metadata Files)**
   - severity: 🟡 warning
   - file: `.task/**`
   - There is an excessive amount of `.task/os/.../*.json` and `workpad.md` files being committed to the repository. These appear to be internal agent session logs/state.
   - **Fix**: Add `.task/` to `.gitignore` or ensure only final task definitions are committed, not every session JSON and evidence log.

3. **Potential Shell Injection / Unsafe Execution**
   - severity: 🟡 warning
   - file: `packages/os/scripts/workspace-watchdog.sh` (implied by diff)
   - The diff shows changes to a shell script for watchdog recovery. Without seeing the full implementation of the `kickstart` logic, there is a risk of unsafe variable expansion in shell scripts.
   - **Fix**: Ensure all variables in the `.sh` script are double-quoted and validated.

4. **Testing Strategy for Daemon Reliability**
   - severity: 🟢 nit
   - file: `packages/os/tests/system-daemon-reliability.test.ts`
   - The PR relies on "focused red coverage" and "Green evidence" in the workpads, but the actual test assertions for `launchctl kickstart -k` (self-safe restart) should be explicitly reviewed for race conditions.
   - **Fix**: Add a specific test case that verifies the PID remains stable or transitions correctly without leaving an orphaned lock file.

## good
- **Test-Driven Approach**: The author used a "Red-Green" cycle with focused test suites before applying production fixes, as evidenced in the workpads.
- **Backward Compatibility**: The implementation of the dual-era MCP transport (falling back to 2024 handshake on method-not-found) is the correct way to handle protocol evolution.
- **Security Hardening**: Flattening the security state to a canonical home directory to prevent replay attacks is a strong improvement.

## verdict
REQUEST_CHANGES

**Reason**: The PR is far too large and contains significant "noise" from agent metadata files. It must be split into functional domains (OS, MCP, Website) and the `.task` session logs must be removed from the commit history.
