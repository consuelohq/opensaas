## [23A-R01-004] Lifecycle diagnostics grow without a bound and are read in full

Inline placement is unavailable because the affected product files are not part of PR #1674's retained documentation-only diff. Exact candidate locations: `packages/os/scripts/lib/lifecycle/diagnostics.ts:37-52` and `packages/os/scripts/lib/native-lifecycle-endpoint.ts:354-360`.

**Medium / P2 / Observability**

Every lifecycle event is appended to one `logs/lifecycle.jsonl` file with `appendFileSync`. No size, age, count, or rotation policy exists in the lifecycle or retention paths. The native diagnostics endpoint then reads the entire file synchronously and splits every line before filtering.

**Concrete risk:** a long-lived or repeatedly failing node can consume disk indefinitely. Diagnostic retrieval becomes progressively more expensive and can create avoidable event-loop stalls or memory spikes precisely during incident recovery. This fails Worker 23a's explicit bounded-diagnostics acceptance gate.

**Recommendation:** introduce a deterministic bounded retention policy for lifecycle diagnostics, such as size-capped rotation with a fixed generation count, and make export read only the bounded tail needed by the API. Preserve mode `0600`, redaction, structured JSONL, and failure isolation.

**Validation:**

- generate substantially more events than the configured bound and prove disk usage remains bounded;
- prove export returns the newest valid redacted events without loading an unbounded file;
- prove rotation cannot follow symlinks outside the managed log directory;
- rerun lifecycle diagnostics and native endpoint regressions.
