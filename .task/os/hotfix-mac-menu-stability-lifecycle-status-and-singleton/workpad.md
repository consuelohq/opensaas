## acceptance criteria

- [x] Root menu width stays compact even when lifecycle history contains a long failure string.
- [x] `Repair required` reflects current machine/service health rather than a stale historical failed update.
- [x] Routine heartbeat polling does not rebuild a presented SwiftUI menu when visible state is unchanged, so pointer/hover interaction stays stable.
- [x] Exactly one Consuelo status-menu app can remain active for the current user, including launches from different app paths.
- [x] Read-only Nodes discovery reuses the enrolled node identity. Signed heartbeats return a sanitized workspace snapshot, cached owner-only, so the menu can discover the cloud node without a second operator login.
- [x] Privileged node mutations remain scope-gated behind operator OAuth; read-only discovery does not weaken management authorization.
- [x] Existing lifecycle endpoints/actions, notifications, and default-node behavior remain intact.
- [x] Focused Swift, lifecycle, heartbeat, OAuth, and node-routing regressions cover the hotfix.

1. [x] Classify menu width, stale health, hover churn, singleton, cloud-node discovery, and auth-boundary failures.
2. [x] Add focused contracts before/with implementation.
3. [x] Implement the smallest runtime/menu fix without introducing a second node registry or stealing browser credentials.
4. [x] Build the actual Swift release target and run focused regressions.
