## implementation notes
- launchd/systemd/Windows/Docker now supervise `scripts/server/supervisor.ts`; `server/main.ts` remains the individual request-worker entrypoint and direct smoke target.
- Default pool size is 1 for a no-routing-change rollout. `CONSUELO_OS_WORKER_COUNT` enables up to 16 deterministic adjacent worker ports; Branch 6 will make Caddy distribute traffic across them.
- Supervisor snapshots are atomically written to `<CONSUELO_HOME>/node/runs/os-worker-pool.json`; `consuelo-reload status` renders pool readiness/restart state.
- `GET /ready` is public for local load-balancer probes and exposes only worker identity/drain state plus existing runtime identity. `/health` remains backward-compatible.
- Workers reject new non-probe requests after draining starts, account active requests, stop accepting traffic, and use bounded forced close only after the drain timeout. Supervised workers also retire if their supervisor parent disappears.
- Crash replacement is slot-local. A transient replacement spawn failure is retried; a healthy sibling is not restarted.
- The node supervisor owns the macOS native lifecycle endpoint and Windows heartbeat scheduler so worker count does not duplicate singleton sidecars.
- Current `stream/os` was merged before final validation; parallel watchdog canonical-restart changes were preserved with no conflict.
