## acceptance criteria

- [x] macOS registers only the first-party `com.consuelo.system` service for the normal OS runtime path; Caddy, cloudflared connector, heartbeat, and watchdog are not independently registered with launchd.
- [x] Caddy and cloudflared remain long-lived across rolling worker updates so public ingress continuity is preserved.
- [x] watchdog/self-healing remains effective without needing an independent LaunchAgent; supervisor crash recovery relies on launchd restarting the first-party host.
- [x] migration retires old Caddy/cloudflared/watchdog LaunchAgents only after the new supervised sidecars are healthy.
- [x] rollback to a legacy runtime can reinstall/restart the old sidecar LaunchAgents.
- [x] uninstall removes the first-party service and remains backward-compatible with leftover legacy sidecar registrations.
- [x] Linux/Windows behavior is unchanged.
- [x] tests cover migration, restart/update continuity, rollback, supervised child restart, and uninstall compatibility.

## key decisions

- Keep `ConsueloServiceHost` thin. Sidecar supervision belongs in the existing Bun supervisor, not Swift.
- Preserve ingress continuity by attaching Caddy/cloudflared to the long-lived supervisor process, not to rolling workers.
- Use launchd KeepAlive on the first-party host as the recovery boundary for supervisor failure.
