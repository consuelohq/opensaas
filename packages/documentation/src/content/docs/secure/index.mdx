Security in Consuelo OS is a chain of boundaries, not one master switch. Identity says **who** is connecting. Authentication proves that identity. Authorization limits **what** the caller may do. Approval pauses sensitive work for a human decision. Transport determines **how** the request reaches the workspace.

<Note>
  Consuelo OS is in preview. These pages document current verified behavior, not every control described in older design reports.
</Note>

## Follow the request

```text
agent or browser
  → Consuelo identity and workspace binding
  → hosted edge route policy
  → signed connector transport
  → local OS authorization
  → tool policy and approval
```

Each hop has a narrower job. A network route does not grant tool access. A valid credential does not approve a destructive action. An installed tool does not become callable without the required scope.

## The shortest useful rule

Give every caller the smallest workspace, route, and tool scope it needs. Keep the local runtime private. Require fresh proof on each protected request. Ask for approval at the point where an action becomes external, destructive, or administrative.

Use [Security reference](/secure/security-reference/) for exact states, lifetimes, route modes, and error codes.
