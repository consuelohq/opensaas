Consuelo OS exposes Model Context Protocol through local stdio for supported coding agents and HTTPS for approved hosted agents.

When the hosted workspace route can reach more than one node, Consuelo resolves the destination before the selected node executes the MCP request. That routing decision is a Consuelo workspace concern, not a new MCP protocol primitive. Default, explicit, task-owned, and work-session-owned routing use the same node-routing layer.

Facade call envelopes may carry a top-level `taskSession` or `workSession`, but never both. A task session follows the node that owns the task worktree. A work session follows the node that owns its local work-session metadata. The filesystem path for a work session stays on that node; central affinity stores only the session identity and owning node.

## Initialize

The gateway speaks JSON-RPC 2.0 and currently returns MCP protocol version `2024-11-05`.

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {}
}
```

The result includes:

```json
{
  "protocolVersion": "2024-11-05",
  "serverInfo": {
    "name": "consuelo-os-gateway",
    "version": "1.0.0"
  },
  "capabilities": {
    "tools": { "listChanged": false },
    "prompts": {},
    "resources": {}
  }
}
```

## Supported methods

| Method | Result | Required scope |
| --- | --- | --- |
| `initialize` | Protocol and server capabilities. | `route:/mcp:read` |
| `notifications/initialized` | Empty result. | `route:/mcp:read` |
| `ping` | Empty result. | `route:/mcp:read` |
| `tools/list` | Enabled OS skills as MCP tools. | `route:/mcp:read` |
| `tools/call` | Calls one OS skill. | Tool-specific scope |
| `prompts/list` | `prompts: []` | `route:/mcp:read` |
| `resources/list` | `resources: []` | `route:/mcp:read` |

The gateway does not currently publish MCP prompts or resources. Facade tools are not directly callable through `tools/call`; the MCP callable surface is OS skills from the effective manifest.

## Tool discovery

Each `tools/list` entry contains:

```json
{
  "name": "sites",
  "title": "Sites",
  "description": "...",
  "inputSchema": { "type": "object" },
  "annotations": {
    "consueloKind": "os-skill",
    "requiredScope": "tool:sites:read",
    "category": "read"
  }
}
```

Disabled skills are removed by the effective manifest before discovery.

## Call a tool

```json
{
  "jsonrpc": "2.0",
  "id": 2,
  "method": "tools/call",
  "params": {
    "name": "sites",
    "arguments": {}
  }
}
```

The result uses MCP text content. Consuelo serializes the skill's structured result or error into the text field and sets `isError` when `CallOutput.ok` is false.

## Gateway errors

Before JSON-RPC execution, route validation can return:

| Code | Meaning |
| --- | --- |
| `INVALID_MCP_REQUEST` | Body is not a JSON-RPC request object. |
| `INVALID_MCP_TOOL_CALL` | `tools/call` has no non-empty tool name. |
| `INVALID_SESSION_ROUTE` | The request supplies conflicting task/work session routing authority. |
| `UNKNOWN_MCP_METHOD` | Method is outside the supported set. |
| `UNSUPPORTED_MCP_TOOL` | Name resolves to a non-skill surface; only OS skills are callable. |

JSON-RPC errors use standard codes for the current cases:

- `-32600` — invalid request;
- `-32601` — method not found;
- `-32602` — invalid `tools/call` parameters.

Consuelo safety admission can reject an MCP request before authentication or tool execution. Those denials use HTTP 200 with a JSON-RPC server error code of `-32040`, a generic `DANGEROUS_MATERIAL_BLOCKED` data code, and an `x-consuelo-request-id` receipt. The receipt lets operators distinguish a request that reached Consuelo OS and was denied locally from a transport failure that never reached the OS boundary. Raw blocked payloads are not included in this telemetry.

Authentication failures keep their HTTP status contract; for example, a missing bearer credential remains HTTP 401. MCP responses that reach the local OS boundary also carry `x-consuelo-request-id` for correlation.

Authorization, missing scopes, expired credentials, and signed-transport errors are defined in [Security reference](/secure/security-reference/).

Node selection can also fail before JSON-RPC execution. `WORKSPACE_NODE_OFFLINE`, `NODE_ROUTE_MISMATCH`, `TASK_NODE_MISMATCH`, `WORK_SESSION_NODE_MISMATCH`, `TASK_WORKSPACE_MISMATCH`, and `WORK_SESSION_WORKSPACE_MISMATCH` are workspace routing errors; they are not MCP method errors. See [Result and error formats](/reference/result-and-error-formats/#node-routing-errors).
