Apps and services are the systems an agent can work with after the agent itself is connected. A local credential, an official CLI, or an API gives the tool access; Consuelo scopes how the agent discovers and calls that tool.

<Note>
  A service can be useful today even when its native Consuelo tool is planned. Each page separates the current CLI or API path from built-in OS support.
</Note>

## Read the status first

Every service page answers two separate questions:

- **Native Consuelo tool** — whether OS already provides a typed provider family.
- **Available today** — whether your agent can use a verified official CLI or API while the native tool is being built.

Current built-in examples include GitHub, Linear, Sentry, outbound Slack posting, and part of the Railway workflow. Other pages provide an external, user-facing implementation path rather than pretending the native wrapper already ships.

## The safe default

Keep authentication on the local node. Verify one read-only operation. Expose the smallest typed surface required. Require approval for writes, deployments, permission changes, billing actions, messages, and destructive operations.

See [Apple Keychain and API keys](/secure/apple-keychain-and-api-keys/) before adding a credential.
