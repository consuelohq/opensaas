> **Native Consuelo tool: Planned**  
> **Available today: Yes — through the official Wrangler CLI and Cloudflare API.**

Use Cloudflare when you need to deploy Workers, inspect deployments, manage environment bindings, work with DNS, and operate tunnels without giving an agent unrestricted account access.

Consuelo plans to provide a focused `cloudflare` tool family. You do not need to wait for that native wrapper: an agent can use the official interface locally now, then turn the smallest proven workflow into a typed OS tool.

## Ask your agent

```text
Set up Cloudflare for this workspace using the official interface linked below.
Keep authentication on the local node and never print the credential.
Start with one read-only verification command.
Then create a typed Consuelo tool exposing only the operations I approve.
Separate read methods from write methods, add structured errors and focused tests,
and require approval for external, destructive, billing, permission, or deployment changes.
```

## Install and authenticate

Use the official Wrangler package from the project you are operating. Start with `bunx wrangler --version`, then authenticate interactively with `bunx wrangler login` or supply a scoped API token to the local process.

Store service credentials with [Apple Keychain and API keys](/secure/apple-keychain-and-api-keys/) or another local process-owned mechanism. Do not put a token in steering, a skill file, a conversation, or a command argument that may be logged.

## Verify before building a tool

Run `bunx wrangler whoami` or another read-only account check before attempting a deployment.

A successful login is not enough. Confirm the selected account, team, project, region, or workspace before the tool can act.

## Proposed Consuelo methods

```text
cloudflare.account.get
cloudflare.workers.list
cloudflare.deploy
cloudflare.logs
cloudflare.dns.list
cloudflare.tunnel.status
```

Useful typed inputs:

```text
accountId
projectPath
environment
command
dryRun
tail
approval
```

The native wrapper should return structured results, redact secret material, expose exact provider errors, and make account or project selection explicit.

## Writes and approvals

Treat deploys, DNS changes, secret updates, route changes, and tunnel mutations as write operations. Require a preview or dry run when the underlying command supports one, then request approval before the live action.

## Native Consuelo roadmap

The planned tool will wrap proven provider operations rather than hide the underlying contract. Until it ships, the official CLI or API remains the source of truth for authentication, flags, limits, and provider behavior.
