Consuelo OS does not currently expose a generic “add any connector” screen. A service is usable only when the current runtime includes a tool or skill contract for it and the required credential can be supplied safely.

## Check support

Before planning a workflow, answer four questions:

1. Is there a manifest-backed tool for the service?
2. Is there a documented credential or managed grant path?
3. Does the tool expose the exact read or write operation needed?
4. Can the connection be verified without putting a secret in the model context?

If any answer is no, treat the connector as unavailable or assisted—not connected.

## Current optional capability families

The internal capability matrix names possible Google, Microsoft, email, CRM, telephony, billing, analytics, and deployment integrations. Those names guide implementation; they are not a promise that every provider is installed or self-service.

## Request a connector

Send the Consuelo team the service, workspace, desired operations, minimum scopes, data residency requirements, and approval expectations. That is enough to determine whether an existing tool can be provisioned or a new contract is needed.

## For tool authors

Do not make a credential-bearing script discoverable merely by placing it in a folder. A production connector needs a typed manifest entry, input validation, secret handling outside prompts, structured failures, permission metadata, focused tests, and a revocation story. The full authoring model belongs in [Build with OS](/build/).
