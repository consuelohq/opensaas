Consuelo OS can work with an agent that speaks MCP stdio or remote MCP, but automatic configuration is deliberately limited to clients with a tested native format.

## Factory Droid

Factory Droid is a supported local client. The installer uses the agent ID `factory`, detects `~/.factory`, and writes `~/.factory/mcp.json` under `mcpServers`.

```bash
export CONSUELO_HOME="${CONSUELO_HOME:-$HOME/.consuelo}"
cd "$CONSUELO_HOME"
bun ./scripts/install.ts --yes --mode local --home "$CONSUELO_HOME" --connect-agent factory --skip-daemons
```

Its server runs `~/.consuelo/bin/consuelo-os-mcp`. The same `verified` handshake rules apply as for Codex and Claude Code.

## Pi

Pi is detectable, but native MCP configuration is currently **unsupported**. The installer recognizes Pi's common macOS and XDG paths so it can report the boundary clearly; it does not write a guessed `mcp.json` format.

Do not pass `--connect-agent pi` expecting a working connection.

## Another local MCP client

For a client without an installer adapter, use its documented stdio MCP configuration only when it can specify:

```text
command: ~/.consuelo/bin/consuelo-os-mcp
working directory: ~/.consuelo
CONSUELO_HOME: ~/.consuelo
```

This is a manual, unverified path. Consuelo will not record that client as `verified`, preserve its config, or troubleshoot a provider-specific format it does not own.

## Another cloud agent

ChatGPT is the only non-placeholder cloud connector in the current Settings model. Grok, Cursor Cloud, and Gemini cloud entries are shown as coming soon, not as setup paths. Use a supported local client or ChatGPT until a remote provider has a verified OAuth and MCP route.
